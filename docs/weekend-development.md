## 拿同一段数据分别开工

从仓库根目录运行下列命令。第一个逐项核对样例的方向、字段、枚举和取消后的预期处理。第二个输出这一段对话中服务端发出的原始 JSON 行，前端可以逐行解析并传入自己的事件入口。第三个输出浏览器发往 Flask 的示例帧，后端可以交给消息处理器。需要重现真实打断顺序时直接按样例里的双向顺序逐帧投递，按方向筛选的两份输出适合分别调试收包。

```sh
python tools/replay_contract.py
python tools/replay_contract.py --case opening-interrupt --emit server
python tools/replay_contract.py --case text-and-memory --emit client
```

四个用例分别是 `opening-interrupt`（欢迎中打断及迟到块）、`text-and-memory`（关闭相机并保存偏好）、`visual-practice`（分类、场景和记忆草稿）、`tts-fallback`（合成超时后改字幕）。想验证自己产生的消息，可以复制一个用例，将对应 `message` 替换成模块输出，再执行 `python tools/replay_contract.py --file 路径`。音频夹具是静音采样，音质和口型用实录验。

## 演示放行

- **先保原基线。** 同一设备、同一批样本并排比较。原有规则、记忆、开聊与取消用例继续通过。语音门槛、2D 资产验收、扩类的逐类指标及其余项以[完整验收表](demo-development-baseline.md#8-demo-验收标准)为准。候选有退步时，保留上一个已验收版本，实验结果另行展示。
- **实测与模拟分别记账。** 离线样例用于让六个人并行开工。周日记录真实服务、权重、输入设备与浏览器上跑通的项目。没有合格旧模型可以回退时，直接登记未达项、复现步骤和负责人。
- **同一项改动留一个可复验结果。** 例如先播放开场，用户在半句中插话，旧音频随后迟到，演示端依然安静；刷新后只恢复当前用户明确保存的偏好。量化检查包括打断停声 P95 ≤ 500 ms、普通回应首声 P95 ≤ 3 s、声音停止与口型归位时差 ≤ 120 ms。
- **一个接口一个合并入口。** 各人以自己的模块目录提小 PR，写清生产方、消费方、运行命令和样例结果。陈尧武协调公共字段变化，生产方与消费方在同一轮更新契约、样例和实现。演示发布使用实际通过回归的提交。
