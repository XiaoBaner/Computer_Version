# 语音微调方案（Qwen3-TTS-12Hz Base）

写给需要审这份方案的人看：要做什么、数据要什么规格、每一步跑什么命令、本机会碰到什么坑、怎么判断训成了。

一句话结论：**官方支持单说话人微调，链路是三步；但 1.7B 全参微调在 24 GB 的 M4 上大概率跑不动，需要先降级到 0.6B 全参或 1.7B + LoRA。**

---

## 1. 两条路，先分清

| | 零样本克隆（现在在用） | 微调（这份方案） |
| --- | --- | --- |
| 数据量 | 5–10 秒参考音 | 30–120 分钟同一人语音 |
| 训练耗时 | 无 | 数小时 |
| 音色稳定性 | 会抖（同一参考三条 F0 差 33 Hz） | 内化进权重，稳定 |
| 情感控制 | 无 | 无（情绪仍来自文本与数据分布） |
| 适用 | 快速试听、换音色 | 定稿音色、长期使用 |

克隆解决"像不像这个声音"，微调解决"每一句是不是同一个声音"。两者都不能凭空造出情感表演——那要靠数据里本来就有情感。

## 2. 数据规格（硬性要求，不合规直接训不了）

来自官方 `finetuning/dataset.py` 的实际约束，不是建议：

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 采样率 | **必须 24 kHz** | 源码里是 `assert sr == 24000`，不是警告，是直接中断 |
| 声道 | 单声道 | 双声道会被降混 |
| 格式 | wav（16-bit PCM 即可） | mp3 先转，别直接喂 |
| 说话人 | **单一** | 官方只支持单说话人；多人要拆成多个数据集分别训 |
| 每条时长 | 3–15 秒 | 太短学不到韵律，太长 batch 内 padding 吃内存 |
| 条数 | 200 条起，800–2000 条较好 | 对应 30–120 分钟 |
| 文本 | **逐字准确**，带标点 | 错一个字，模型就把那个音学错；标点影响停顿 |
| 参考音 | 全数据集**同一条** `ref_audio` | 官方明确建议统一，否则音色会飘 |

JSONL 每行三个字段：

```jsonl
{"audio":"/abs/path/utt0001.wav","text":"听起来今天挺累的。","ref_audio":"/abs/path/ref.wav"}
{"audio":"/abs/path/utt0002.wav","text":"你不用马上回答。想说的时候，我都在。","ref_audio":"/abs/path/ref.wav"}
```

`ref_audio` 单独挑一条 5–10 秒、语气自然、没有口误的，别用训练集里的句子去当参考（会和某一条过拟合）。

### 2.1 手上数据实测（2026-11-26）

可能用的合法语料是あみたろ MANA 语料的「夜更かし」风格（见 `voice-sources.md`）。实测：

| 项 | 值 |
| --- | --- |
| 句数 | 228（去重后 228，无重名） |
| 总时长 | **9.4 分钟**（中位 2.39 秒，最长 5.2 秒） |
| ≥ 3 秒的句子 | 45 条 / 2.5 分钟 |
| ≥ 1.5 秒的句子 | 219 条 / 9.2 分钟 |
| 转写 | 100% 精确，来自 `mana-corpus.txt`，无 ASR 误差 |

**结论：MANA 单独不够。** 官方推荐 30–120 分钟，MANA 只有 9.4 分钟；而且官方自己的 About 里就写了「不建议只用 MANA 语料训练，请与同一声音的 ITA 语料一起用」。

补齐的唯一来源是同一人、同一风格、同样条款的 ITA 语料：`ITAcorpus_amitaro_yofukashi_1.1.zip`（185 MB，424 句，含 RECITATION324 + EMOTION100，转写在 `github.com/mmorise/ita-corpus`）。两者相加约 **652 句 / 30 分钟以上**，刚好够到下限。

代码里只校验采样率，不校验时长（`dataset.py` 只有 `assert sr == 24000`），所以 2 秒的句子技术上能进训练，只是学不到长句的韵律。`build_corpus_jsonl.py` 的 `--min-s` 就是为此留的开关，默认 3.0，实际用 1.5 保留 219 条。

## 3. 流水线三步

### 第一步：抽取 audio_codes

```bash
python prepare_data.py \
  --device mps \
  --tokenizer_model_path ~/.cache/modelscope/models/Qwen--Qwen3-TTS-12Hz-1.7B-Base/snapshots/master/speech_tokenizer \
  --input_jsonl train_raw.jsonl \
  --output_jsonl train_with_codes.jsonl
```

这一步把音频编码成 12 Hz 的离散 token，是纯推理，MPS 能跑。产物体积约等于原音频的 1/50。

### 第二步：SFT

```bash
python sft_12hz.py \
  --init_model_path <本地 Base 模型目录> \
  --output_model_path output \
  --train_jsonl train_with_codes.jsonl \
  --batch_size 2 \
  --lr 2e-5 \
  --num_epochs 3 \
  --speaker_name psyche
```

脚本用 `accelerate`，梯度累积默认 4、混合精度 bf16，每个 epoch 存一个 checkpoint。

> 注意：仓库 README 写的是 `lr 2e-6 / epochs 10 / batch 32`，脚本默认值是 `2e-5 / 3 / 2`。两处不一致，**按脚本默认值先跑**，再拿 checkpoint 逐个试听决定取哪个 epoch——通常第 2–3 个就够，训多了会把参考音的语气也一起背下来。

### 第三步：推理验证

用训出来的 checkpoint 生成同一组测试句，和零样本克隆版、真人原音三方对比。

## 4. 本机能不能跑（这是方案的薄弱处）

M4 / 24 GB 统一内存，粗算全参微调的常驻开销：

| 项 | 1.7B | 0.6B |
| --- | ---: | ---: |
| 权重（bf16） | 3.4 GB | 1.2 GB |
| 梯度（bf16） | 3.4 GB | 1.2 GB |
| AdamW 状态（fp32 ×2） | 13.6 GB | 4.8 GB |
| 激活 + 注意力 | 视序列长度 | 视序列长度 |
| **合计（不含激活）** | **≈20.4 GB** | **≈7.2 GB** |

24 GB 里还要留系统和其他进程。**1.7B 全参基本没戏，0.6B 全参有希望。** 因此三条降级路线，按优先级：

1. **0.6B 全参**：先跑通，看效果。0.6B 不支持 instruct，但微调的是 Base，音色和无指令生成不受影响，对"稳定音色"这个目标够用
2. **1.7B + LoRA**：改 `sft_12hz.py`，冻结主干只训低秩适配器，显存降到 6–8 GB；代价是要自己写注入逻辑，且官方没有现成脚本
3. **1.7B 冻结大部分层**：只训 talker 顶层，介于两者之间

先做第 1 条。跑通以后再决定要不要为 1.7B 写 LoRA。

耗时估算（M4，bf16，batch 2 × 累积 4，有效 batch 8）：800 条、3 个 epoch 大致 4–8 小时。可以先拿 100 条跑 1 个 epoch 验证链路，别一上来就挂通宵。

## 5. 怎么判断训成了

三个层面，缺一不可：

**客观**
- ASR 回读：用 Whisper 把合成语音转回文字，算字错率。超过 5% 说明发音开始漂
- F0 分布：和真人数据比均值、标准差。偏离超过 15 Hz 说明音色没学住
- 时长分布：同样字数下，语速应落在真人数据的 ±15% 内

**主观**
- 盲听三方对比：真人原音 / 零样本克隆 / 微调结果，同一组 8 句
- 只问一个问题："哪一条最像同一个人在自然说话"——不问"哪个更好听"，好听会被音色带偏

**退化检查**
- 训完有没有出现"每句开头都同一个调"（过拟合到参考音）
- 长句（20 字以上）会不会中途换人

## 6. 风险

| 风险 | 应对 |
| --- | --- |
| 24 GB 内存不够 | 走 0.6B 或 LoRA，见 §4 |
| 数据文本有错字 | 训前用 ASR 反向校验一遍，标出低置信度的句子人工听 |
| 过拟合参考音 | 少训几个 epoch，checkpoint 逐个试听 |
| 数据本身平淡 | 微调只能复制数据里的表现力，数据平淡出来就平淡——这条无解，只能换数据 |
| 官方脚本与 README 参数不一致 | 以脚本为准，README 当参考 |
